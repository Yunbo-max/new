# R015-B — Across-query temperature constraints and head-local KV observability

Date 2026-10-24. Source checkpoint `50b360de8cbb97092fd82ed968dabe113d425272`. Subjects: active QKV-B parent and QKV-B-precision-radial-collision child. Evidence is formulae, original pinned Qwen3 code and CPU fixtures only.

## B parent — exact price of sharing a deployed temperature across queries

**Operator and information.** Let \(h_i\in\mathbb R^D\) be the after-Value/\(W_O\) tangent of a radial key perturbation at query \(i\), and \(g_i\in\mathbb R^D\) the after-output ordinary scalar-temperature tangent. At small \(\eta\), a repair coefficient \(c_i\) leaves \(\eta(h_i-c_i g_i)\). A privileged oracle can choose one \(c_i\) per query; an ordinary fixed global-temperature control must use the **same** \(c\) across all evaluation queries and fit it using calibration only.

**Consequential exact identity.** For nonzero \(g_i\), define \(c_i^*=(g_i^\top h_i)/\|g_i\|^2\) and \(\bar c=\sum_i g_i^\top h_i/\sum_i\|g_i\|^2\). Then
\[
\sum_i\|h_i-\bar c g_i\|^2-\sum_i\|h_i-c_i^*g_i\|^2
=\sum_i\|g_i\|^2(c_i^*-\bar c)^2\geq0.
\]
This is weighted least-squares projection, not a new theorem. Under a nonnegative-temperature constraint, this formula describes local feasible perturbations near temperature 1; it is not automatically a globally optimal finite-temperature solution.

**Executed CPU witness.** Four queries in output dimension two, \(g_i=(1,0)\), \(h_i=(c_i,0.3)\), \(c_i=(-1,0,1,2)\), \(\eta=.1\). Every per-query temperature \(1+\eta c_i\) lies in [0.9,1.2]. The total squared first-order error with privileged per-query repair is **0.0036**; one shared temperature 1.05 gives **0.0536**, excess **0.0500**, exactly equal to the weighted variance term. In the real model an expressive query-conditioned temperature predictor could learn \(c_i\) if its input is sufficient; it must be given the same model/parameter/compute/training budget, not dismissed.

**Closest alternatives / falsifier.** R014's OptR, QKNorm/QUEST, ordinary Q-head temperature calibration, per-query SFT/MLP, \(V/W_O\) tuning and matched retraining are strong baselines. Evaluate native post-\(V,W_O\) residual plus next-token NLL with fixed validation/test query splits and identical masks/RoPE; log privilege used by row oracles. If those simple repairs span natural \(h_i\) or the task gradient annihilates it, park novelty. Model weights and independent design review were not used.

## B precision child — which information actually survives in a shared-KV group?

**Precise tensor path.** The pinned Qwen3 implementation (`huggingface/transformers@5f4ecf2d9f867a1255131d2461d75793c0cf1db2`, `modeling_qwen3.py`) normalizes Q/K per head after linear projections in FP32, casts the result to the input dtype, then multiplies gain, applies RoPE and groups attention. V comes from a separate *unnormalized* projection; the residual path also survives. A BF16 equality of normalized K values therefore does **not** establish a collision of the complete decoder state.

**New mathematical boundary.** Let hidden state \(x\in\mathbb R^m\), local cache observer \((\operatorname{BF16Norm}(W_K x),W_Vx)\), and consider the radial pair \(x,cx\) for \(c>0\). If normalized K casts match, these two states remain distinguishable **if and only if** \((c-1)W_Vx\ne0\) through that particular V path. For \(W_V\) with rank \(r<m\), the kernel has dimension \(m-r\), so head-local radial indistinguishability is feasible; another V head or the residual may remove that ambiguity. This criterion is for the *cache-accessible tensor interface*, not task-level equivalence after all layers.

**CPU witness.** Take \(m=6\), a 2×6 local V projection selecting coordinates 1–2, and a separate 2×6 K projection selecting coordinates 3–4. For \(x=(0,0,1,1,0,0)\) and \(2x\), the source-ordered BF16 KNorm tensors are identical, and local V is zero for both; a second V projection selecting coordinates 3–4 distinguishes them with Euclidean gap \(\sqrt2\). The first head's V nullspace has dimension four. In the proposed Qwen3-0.6B (hidden1024, one KV Value head128), the per-head Value nullspace is **at least 896D** by rank-nullity, but the concatenation of all eight KV Value heads is 1024D and could be full-rank: **actual trained singular values have not been inspected.** This is a capacity/observability statement, not evidence that natural inputs fall into that nullspace.

**Falsifier and reviewer gate.** The native Qwen study must freeze the exact weight revision, input dtype, backend (eager/SDPA/Flash), learned q/k gamma, K/V/WO/residual hooks, tokenizer/window hashes, and downstream NLL. Test FP32 norm, BF16 norm, sidecar radius and raw QK at equal retained bytes/FLOPs. If the trained V/residual paths carry all task-important radial information, a new K-radius module is unnecessary. Neither a model run nor formal independent acceptance has occurred.
