## QKV-C / D1-D4: a vanishing average score error need not mean small attention error
R007's controlled cache: two pairs (k,v)=(+1,+1),(-1,-1), and N pairs(0,0), query scaled logit t. Forced mean/centroid compression of the special pair yields 0, full output:
  f_N(t)=2sinh(t)/(N+2cosh(t)).
Now parameterize t_N=log N+c for FIXED c∈R. Dividing numerator/denominator by N:
  f_N(t_N) -> e^c/(1+e^c)=sigmoid(c).
Yet global mean squared logits=2(log N+c)²/(N+2) ->0.
Thus for large N an average-logit error can vanish while task-visible special-pair output remains O(1). The mechanism is a rare logit of order log N; it is not necessarily feasible for arbitrarily large N under bounded per-head query/key norms. With N=65536 and c=-2,0,2: output .11920292,.4999999998,.88079708; mean squares .0025217,.0037534,.0052293 (CPU evaluated).
Countercontrol: if rare-vs-background score advantage is bounded by L independent of N, rare-token softmax mass is at most m exp(L)/(N+m exp(L)) against N background scores0 and m rare entries (for scores≤L), so rare mass vanishes with N. This explains why the R007/R009 toy cannot automatically transfer to native constant-dimensional normalized Q/K. Only measure real logit maxima/quantiles and effective total positions under identical masks.
Closest actual methods: R005 ResKV/MomentKV and R007 directional dilution; no novelty for rare softmax mass concentration. Native falsifier: original cache almost always retains important high-logit keys, query scores bounded far below log N, or equal-byte exact selection dominates all summary variants. Next actor: freeze actual model/query-window distribution and measure max logits relative to log context length, downstream output after V, data-dependent retained token fraction and equal-byte controls.

## QKV-C-unsafe-moment-correction / D1-D5: a computable sufficient certificate
MomentKV v1 https://arxiv.org/html/2606.01563v1 Eq9/11/12 stores E count, means and sum v*k^T, uses first-order E estimate fhat_E=mu_v+C x and underestimated mass Zhat_E=n exp(x^T mu_k), where x=q/sqrt(d). With retained true f_R,Z_R, it predicts
 hat y=f_R + hat w(fhat_E-f_R),  hat w=Zhat_E/(Z_R+Zhat_E).
Paper Appendix B.2 claims unconditional dominance of this correction over plain eviction. R008 provides reachable full-formula exceptions, and the current original primary text was reread and confirms its wording. Search for a verified public author code repository by MomentKV title/name did NOT identify one; Eq/Algorithm evidence ≠ official implementation replication.

Build a conservative **bounded-information** safety certificate, charging auxiliary stored maxima as new memory:
Let E-centered query scores delta_i=x^T(k_i-mu_k), with |delta_i|≤eta and zero sum; ||v_i||≤Vmax across both retained and evicted sets. A safe eta can be obtained from a retained scalar Kmax=max_evicted||k_i|| via eta≤||x||(Kmax+||mu_k||); Vmax can be an extra retained running scalar norm envelope. Let
 r = Z_E/Zhat_E =mean_E exp(delta_i).
Since mean delta=0, Jensen+Taylor give
 1≤r≤rmax=min(exp(eta), 1+(exp(eta)/2)eta²).
Set w(r)=r Zhat_E/(Z_R+r Zhat_E). Then 0≤w-w_hat≤w(rmax)-w_hat=Delta_w.
Writing C=mean[(v_i-mu_v)(k_i-mu_k)^T] (available from moments), Taylor gives
 ||f_E-fhat_E|| ≤ B_E :=(exp(eta)/2)eta²(2Vmax+||C x||).
The unknown true full output satisfies, with d=hat y-f_R:
 ||y_true-hat y|| ≤ B := 2Vmax Delta_w + w_hat B_E.
This bound charges key/value-norm metadata, does not silently use the true lost keys, and is conservative (especially for eta≫1).
**Sufficient improvement rule.** Since y_true=hat y+e, ||e||≤B, the difference between plain-eviction squared error and corrected squared error is
 ||y_true-f_R||²-||y_true-hat y||² = ||d||²+2<d,e>
 ≥ ||d||²-2||d||B.
Consequently, if d≠0 and B<||d||/2, the corrected output is GUARANTEED strictly closer than plain eviction for every full cache compatible with those stored upper bounds. If the certificate fails, apply no correction; failure to certify is NOT proof correction would hurt.
CPU cases, one retained (key0,value b), evicted keys +/-t, values +/-1:
  (i) t=.05,b=1: corrected .3666667, full .36637518, plain error .6336248, corrected .00029149, bound B=.00237945 <|d|/2=.316667 => certified safe.
  (ii) t=8,b=4: corrected6.666667, full1.00100583, plain error2.998994, corrected5.665661, B>1e6 => not certified, genuinely harmful.
  (iii) t=1,b=tanh1: plain FULL output exactly right, correction error .1589372, B≈3.035 => not certified.
This is an analytical/tiny-CPU test, NOT a claim that this conservative gate improves realistic performance. A trivial no-correction policy is universally non-worsening; this gate may rarely pass in practice. Independent work already handles random-sampling error certificates (Xie et al. https://arxiv.org/html/2607.21475v1), DefensiveKV handles worst-case score aggregation https://arxiv.org/html/2510.13334, and RestoreKV uses full pre-eviction cache access. New architecture/novelty NOT established.
**Critical falsifiers/controls:** how often does the gate pass under production Qwen3 query norms? Does storing Kmax,Vmax and C use more bytes than same-budget extra exact KV, clipping or refetch? Does a production implementation already clamp the approximation? If no useful certified region or any matched baseline dominates, park this child. Need official source code, exact model/dataset manifest, separate reviewer, and native tests before implementation admission.
