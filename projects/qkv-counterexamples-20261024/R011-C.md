# R011-C — Planted-key conditionality and same-statistics impossibility of safe moment switching

## QKV-C: IID isotropic rarity does not transfer to a retrieval task with a planted match

**Interface.** Head dimension `d=128`, unit-gain normalized key/query norms `sqrt(d)`, query aligned exactly with one special key. Its content logit is `sqrt(d)=11.3137085`. Background of `N=65536` keys is independently sampled from uniform directions on the `d-1` sphere; their logits are `sqrt(d)*Z/sqrt(Z^2+chi-square_(d-1))`, with one dimension `Z~N(0,1)`. This is the *exact* spherical null marginal; the special key is *not* drawn from the null but planted conditional on the query.

With 120 independent background samples, the special key's attention mass is **0.43189** on average (5th–95th percentile about **0.42959–0.43365**). A CLT estimate `exp(sqrt(d))/(exp(sqrt(d))+N*exp(1/2))` predicts **0.43128**. This contrasts with R010's `9.38e-87` union bound for the probability of finding such a match among *only iid unconditioned isotropic keys*. Both results are correct because they apply to different generative processes. A targeted retrieval task explicitly conditions a key on the query, invalidating the iid sphere-tail explanation for success or failure.

**Missing-real-model assumptions.** Learned Q/K projections, RoPE relative positions, value/out projection, masked positions, sink behavior, softmax numerical clipping, actual learned gamma and distractor score correlations could all change the planted share. The toy does not show that MomentKV/ResKV evicts this aligned token or that a language-model task improves. It does demonstrate a test design rule: measure recall conditioned on a **known relevant key** as well as unconditional logit histograms, and predeclare where the relevant key was selected/evicted. Full-cache failures must be reported, not filtered out.

**Novelty/prior art.** Retrieval needles and heavy-hitter cache selection are established; the 2026 certified sparse-attention and randomized sampling papers already handle heavy-tail issues. A new QKV method must beat simple exact-selection and equal-byte baselines. The nearby `Certified Sparse Attention via Perturbed Retrieval` (Runguo Li, arXiv:2610.24991v1, submitted 18 Oct 2026) provides per-query certificates and an O(eps^-2 log 1/delta) value-reading bound, but crucially uses a coarse scan over **all retained original keys**; that is an access model different from permanent deletion of old KV. Do not equate value reads with total stored bytes or pretend the scanner solves post-deletion reconstruction.

**Next actor/falsifier.** Pin Qwen3 and query-switch synthetic retrieval records plus long-document baseline. Test score advantage relative to the *measured* background log-sum-exp, rather than `log N` alone. Measure how often targeted high-score entries were evicted and whether more exact KV at the same total bytes dominates learned or moment summaries. If all relevant matches are retained, the proposed compression-failure mechanism is not present.

## QKV-C-unsafe-moment-correction: Identical moment memory supports opposite optimal actions

**Primary paper.** MomentKV v1 (https://arxiv.org/html/2606.01563v1) Appendix B.2 explicitly asserts an unconditional pointwise dominance of first-order correction over plain eviction. R008–R010 supplied equation-level counterexamples and a conservative sufficient repair certificate; none was a native author-code replication. This round asks whether *a deterministic post-deletion gate* can decide correction for every cache based only on the same stored moments.

**Two worlds, same state.** Let evicted keys `k=(-1,0,+1)`, values `v_s=k+s*4*(1,-2,1)`, with hidden `s∈{-1,+1}`. Retain one key with future logit 0 and scalar value 2. For both worlds the exact stored statistics are `(n,sum(k),sum(v),sum(k*v))=(3,0,0,2)`. The MomentKV first-order output is 1, while plain eviction output is 2. But at future query yielding scores `(-1,0,+1)`:

| Hidden world | True full output | Plain absolute error | Corrected absolute error | Better action |
|---|---:|---:|---:|---|
| s=+1 | 1.70955009 | 0.29044991 | 0.70955009 | Evict-only |
| s=-1 | 0.00113196 | 1.99886804 | 0.99886804 | Correct |

The runtime observes the *same moment statistics and retained cache/query* in each world, so no deterministic switch based ONLY on them can choose the pointwise better action in both. This is a restricted-memory no-identification argument, closely related to Xie (arXiv:2607.21475v1), **not** an invented new impossibility theorem.

**Exact average-case consequence.** Under absolute error and prior `p=P(s=-1)`, correction is Bayes-optimal iff

`p * 1.000000 > (1-p) * 0.4191001837585`, or `p>0.29532811605`.

Thus prior knowledge (or extra retained bits) can justify a decision *on average*, but cannot make it an unconditional safety certificate. One information bit identifying s fixes this **single** pair; with N independent hidden pairings the total bit cost can scale with N (R006). The statement is independent of the user choosing to use a model at all.

**External method equivalence and access accounting.** Xie 2607.21475 uses randomized tail retention/inclusion probabilities to identify variance; arXiv:2610.24991 uses randomized per-query retrieval, nested samples, and a coarse all-keys scan; Runtime-Certified Bounded-Error Quantized Attention (2605.20868) retains exact originals in CPU RAM for fallback. These have *different information access and resource requirements*, but collectively preclude claiming generic certificates, randomization, or reference fallback as unexplored. For dense MomentKV at d=128, R010's 66,576-byte per-head FP32 moment/metadata accounting must be compared with an equal-byte exact entry allocation, not with an equal *token count*.

**Falsification plan.** First, a **different real Work reviewer** must check paper equations and official implementation once identified, including eviction selection, all denominators/masks and cache-state timing. Then a separately approved native executor can compare (i) plain eviction, (ii) MomentKV full code, (iii) clipped/abstaining repairs, (iv) extra exact KV under matched total bytes, (v) certified sampling methods with their full-key scan and original-cache access disclosed. Report per-head outputs, next-token KL and task errors on ALL examples; include non-harm cases. If this counterexample vanishes under actual code, revise equation-to-code applicability. No actual Qwen run or authorized cost was incurred here.
