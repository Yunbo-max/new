## QKV-B / D1-D4: KL residual after strongest global row temperature
Let base logits s_j and p=softmax(s). A scalar key-radial perturbation multiplies content logits by exp(eta*a_j), where a_j=log(r_j/r0); write s_eta,j=s_j exp(eta*a_j). For infinitesimal eta, u_j=ds_eta,j/deta at zero =s_j a_j. A one-row scalar temperature can mimic only s ->(1+c eta)s. The local KL divergence minimized over c is, for Var_p(s)>0,
  inf_c KL[softmax(s_eta) || softmax((1+c eta)s)]
    = eta²/2 [Var_p(u)-Cov_p(u,s)²/Var_p(s)] +O(eta³).
This is simply the softmax Fisher-information quadratic form projected away from the temperature direction, not a novel QK operator. The bracket is nonnegative by Cauchy-Schwarz and zero iff the perturbation is scalar-temperature equivalent up to an additive constant in logits (p-almost surely).
CPU double-precision witness: s=(1,0,-1), radius ratios=(2,1,0.7), u=s*log(r). Fisher residual coefficient .0380631658. At eta=.05 numerical optimal scalar-temp KL=4.76105e-5 versus predicted quadratic4.75790e-5; eta=.1 KL .000190445 versus quadratic .000190316; eta=.2 KL .000760156 vs quadratic .000761263. Strong same-information CONTROL is a row-oracle scalar temperature, not just uncalibrated qnorm.
CRUCIAL output caveat: with all values identical, V^T(p_eta-q_alpha)=0 although KL>0; with head output projection/downstream readout, the effective perturbation may remain invisible. R005/R006 already show rank conditions. Thus a nonzero Fisher residual is a sensitive diagnostic, not evidence for better task quality.

## QKV-B-precision-radial-collision / D1-D4: scale-two exact-equality frequency in actual source-order cast
Pinned implementation https://github.com/huggingface/transformers/blob/5f4ecf2d9f867a1255131d2461d75793c0cf1db2/src/transformers/models/qwen3/modeling_qwen3.py . It accumulates normalization in float32 but converts to input dtype BEFORE learned gain. With input x and 2x, eps1e-6, head_dim128, unit gain, CPU script emulating the exact order measured 1,000 seeded independent N(0,I) vectors cast to each dtype first:
- BF16: entire128-vector equality 995/1000=99.5%; component equality about99.9937%.
- FP16: entire-vector equality 936/1000=93.6%; component equality about99.943%.
- FP32: entire-vector equality0/1000 in this fixture.
For all-ones versus all-twos inputs, BF16 and FP16 cast outputs are exactly identical (component1.0), whereas FP32 outputs .9999995232 and .9999998808 differ. The collision survives any identical subsequent gain multiplication; it is NOT a statement about actual Qwen3 learned weights/activation shapes, fused kernels, V, RoPE, positions or downstream behavior.
Over the reals, epsilon>0 with nonzero gains makes the norm operation injective; the contrast for x->2x in high-radius regime is 1+3epsilon/(8u)+O((epsilon/u)^2) where u=||x||²/d. FP rounding is the mechanism. A per-token scale/norm side channel or FP32 cast is an obvious simple repair at a measurable cost; raw QK plus stable scaling is another.
