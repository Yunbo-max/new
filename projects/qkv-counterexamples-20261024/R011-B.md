## QKV-B: Distinct query heads can each change, yet their group-output change is zero

**Operator and admissible information.** Consider two query heads in the same GQA group sharing keys and scalar values `V=(1,0,-1)` for three visible tokens. Each head has projected logits `t_h*s`, `s=(1,0,-1)`, but different head query scales `t_1=1`, `t_2>1`. A key-radial perturbation multiplies each content logit by `(r_j)^eta`, `r=(2,1,.7)`, `eta=.3`. Define `h(t,eta)=softmax(t*s*r^eta)^T V` and change `Delta(t)=h(t,eta)-h(t,0)`.

By continuity, `Delta(t)` first increases and then decays as attention saturates. Solving `Delta(t_2)=Delta(1)` on a predeclared upper branch yields `t_2≈1.82173237`. Each head changes by **+0.04932984**; each head's output mismatch is nonzero, and head1's probability KL from base is **0.00466538**. With ordinary output-projection blocks `W_O=(+1,-1)`, however, the group's output is `h(1,eta)-h(t_2,eta)`. The baseline group output is **-0.24458324** (nonzero, so not an identically dead group), and the perturbation changes it by only `6.7e-16` in float64.

This is a **constructed exact GQA-matched countercontrol**, not a claim that pretrained `W_O` learns such cancellation. The result strengthens R010: even measuring *nonzero individual head outputs* is insufficient to establish a task-relevant difference after the complete GQA output projection. The only meaningful criterion must account for all query heads sharing K/V and their actual W_O blocks, plus downstream nonlinear/residual effects. Query-only temperature, value maps, projection and retraining remain much simpler baseline repairs. The idea is well within linear algebra of multihead outputs; no novel architecture claim is supported.

**Falsifier.** In a pinned Qwen3-0.6B checkpoint, record the full value-projected GQA group tangent `sum_h W_O,h Delta_h` and compare held-out NLL/accuracy after all residual/MLP effects. If isolated head norms predict no downstream harm or matched simple controls solve it, stop this branch's method design. Keep loss measurement after masked positions and actual RoPE.

## QKV-B-precision-radial-collision: The condition number predicts dtype phase boundaries

Pinned Transformers Qwen3 source (v4.51.3 commit `5f4ecf2d9f867a1255131d2461d75793c0cf1db2`) casts projected head Q/K to FP32, normalizes as `x/sqrt(u+epsilon)` with `u=mean(x^2)`, casts back to input dtype, and then multiplies learned gains before RoPE.

For scalar radial rescaling `x->a x`, the *local log-radius sensitivity* is exactly `epsilon/(u+epsilon)`; the inverse radial condition factor is `kappa_rad=(u+epsilon)/epsilon=1+u/epsilon`. For the finite `a=2` contrast, ideal normalized amplitude ratio is `2*sqrt(u+eps)/sqrt(4u+eps)`, which approaches 1 at large `u/eps`. Thus meaningful *recoverability* is governed by epsilon versus input norm and machine precision. Over reals and nonzero gain the map is injective, but reconstructing original radii from rounded output can be extremely ill-conditioned.

**Executed CPU scale sweep.** 1000 distinct N(0,I) unit-RMS 128D vectors per `u/eps` level, seed 20261024, PyTorch CPU; inputs cast to each dtype BEFORE the RMSNorm, output cast before gain. At `u/eps=1e3`, full-vector equality under `x->2x` is BF16 0.6%, FP16 0%, FP32 0%; at `1e4`, BF16 **95.1%**, FP16 **63.6%**, FP32 0%; at `1e6` both BF16 and FP16 **100%**, FP32 0%; at `1e8` all three are **100%**. Collision fraction is not exactly monotonic across intermediate scales because of floating rounding grids. This is a numerical precision phase map, not a native task effect.

**Primary-source context.** The community repository `yyfenghuang/qwen3-qk-norm` reports a real Qwen3-0.6B forward-pass study with 200 MMLU-Redux prompts and a 4096-token sequence; README claims substantial pre/post norm compression, but the raw `results/qk_stats.json` is NOT committed and these measurements were NOT independently rerun here. Its description of RMSNorm as scale invariant is only approximate for eps>0. The source can inform pre-norm scale hypotheses, not establish Qwen failure rates. Ordinary FP32, learned-gain, scalar sidecar, stable raw QK, same-budget matching and native outcome checks are still missing.
