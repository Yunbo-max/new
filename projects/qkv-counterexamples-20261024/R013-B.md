## QKV-B: Every row can be exactly temperature-repaired while no one calibration temperature repairs all rows

**D1 — Operator and timing.** Consider exactly two fixed post-normalized keys `k1=e1`, `k2=e2` and a fixed *per-key* radial intervention `f=(2^.2,.7^.2)` applied to their scores. For any query q with original scores `(s1,s2)=(q^T k1,q^T k2)`, altered scores are `(f1*s1,f2*s2)`; this uses the SAME factors for every query, not head-specific distortions. A positive single-row temperature matches the attention distribution when

`alpha(q) = [f1*s1-f2*s2]/[s1-s2] > 0`, provided original score gap nonzero. A single deployed constant `alpha` matches EVERY query in a spanning set only if the vectors `f1*k1-f2*k2` and `k1-k2` are proportional, a nongeneric constraint. Note that query-dependent temperature predictors would be a stronger and familiar control.

**D2–D3 — Two queries, exact CPU witness.** Take `q_a=(1,-1)`, `q_b=(2,-.2)`, the same `k1,k2`, eta=.2, and the same f. Both rows are individually repaired exactly, with `alpha_a=1.039924135`, `alpha_b=1.128921224`, all positive. A single optimally fitted global `alpha=1.083051849` yields a nonzero sum of row KL losses `.000731577258`; per-row oracle KL is 0 to floating precision. Thus individual-row oracle success is not evidence a calibration fitted on other queries can reproduce the same operation. This is simply linear-algebra/calibration generalization, not a new architecture.

**D4 — Closest methods.** QKNorm; QUEST (ICLR 2026, `https://arxiv.org/abs/2604.00199`) allows query-controlled sharpness; an MLP of q can learn a query temperature. R012 has already shown that two Q-head temperatures may match a particular 2D GQA output despite positive headwise KL. That result remains true for its exact per-sample interface, but cannot be extrapolated to held-out-query global calibration. Recent WitCert (arXiv:2607.28699) also empirically documents error cancellation, so a novel headwise-calibration architecture claim would have substantial prior-art burden.

**D5–D6 — Native falsifier.** With actual Qwen3 Q/K/V, hold out entire query-context distributions while fitting global/per-head/query-feature temperatures on independent calibration data; compare privileged per-row oracle and post-value/output/n-token loss separately. A novel radial control is motivated only by a downstream benefit beyond equal-information existing predictors, `V/W_O` reparameterizations and matched retraining. **Status:** `deep_incomplete` pending pretrained model/labels and separate reviewer.

## QKV-B-precision-radial-collision: Collision of K is not collision of the whole KV state

**D1–D3.** In the pinned Qwen3Attention operator, projected K passes through head RMSNorm, then RoPE; V is generated separately by `W_V x` without this normalization (modeling_qwen3.py, Transformers immutable commit `5f4ecf2d9f867a1255131d2461d75793c0cf1db2`). For BF16 x=ones(128) and 2x, the displayed norm operator gives *identical* K (R008–R012). But if `W_V x ≠0`, linear V differs by factor 2, absent saturation/underflow. New CPU check with seed 20261024 and a random 128×128 linear V map confirmed identical normalized BF16 K but V norm `10.74297 -> 21.48594` (exact ratio 2). Therefore the pair `(K,V)` is distinguishable even when K is not.

More formally, if the concatenated `W_V` across ALL KV heads has full column rank, `x↦(normalize(W_K x), W_V x)` is injective over real arithmetic even if normalization is many-to-one. For Qwen3-0.6B's stated hidden size 1024, 8 KV heads × 128 head dimensions make a square 1024×1024 aggregate V projection; full rank is *conditional*, not verified for the trained weights and it does not imply efficient reconstruction from V under BF16 quantization. Each individual KV-head V map has a large kernel. Residual and value readout may or may not expose the signal to the task.

**D4–D6.** QK-RMSNorm and radial decomposition are already established. A new key-radius sidecar needs to show that information available in V, ordinary residual pathways, raw-QK baselines and `W_O` cannot solve task-level loss at matched resources. Observe actual pretrained K-collision distribution, post-RoPE Key/Value pairs and final next-token KL/NLL, with calibrated scalar/FP32 controls. **Stage:** mathematical negative control, native relevance unknown, `deep_incomplete`.
