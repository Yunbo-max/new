## C parent: adversarial log-N score margins versus isotropic sphere probabilities

For head dim d with Q/K RMSNorm applied before RoPE, post-gain vectors obey ||q||<=sqrt(d)||gamma_q||inf and ||k||<=sqrt(d)||gamma_k||inf, so score |q^Tk|/sqrt(d)<=sqrt(d)||gamma_q||inf||gamma_k||inf. RoPE preserves vector norms. At d=128 and unit gains, the ceiling 11.3137 exceeds ln(65536)=11.09035. The rare +/-t needle from R007/R009 is therefore *theoretically* possible for some highly aligned normalized vectors.

Under the different null of **independent isotropic** unit-sphere Q/K directions with both vectors of norm sqrt(d), score=sqrt(d)cos(theta). For N candidates and logit advantage t≈ln N, the exact single-key spherical-cap probability is

\[ p=\tfrac12 I_{1-(\ln N)^2/d}\left(\tfrac{d-1}{2},\tfrac12\right), \]

when lnN<sqrt(d). The union bound is Np. For N=8192, d128: necessary cosine~0.79646, union <=6.51e-26. For N=65536: cosine~0.980258, p~1.431e-91 and union <=9.378e-87. These are genuine null-model calculations, not statements about pretrained Qwen distributions. Real Q/K may have learned centers, biases, RoPE distance preference and correlated history; TriAttention (ICML2026) explicitly studies this. Negative real attention logits or nonunit learned gains change the relevant margin; record these, not just max absolute scores.

**Next task:** measure per-layer/head score quantiles versus ln context length under learned gamma/RoPE, plus V/WO sensitivity; compare byte-matched exact retention, ResKV/MomentKV and TriAttention. **Falsifier:** native logit margins do not reach these scales, or simple exact-key retention removes task loss.

## C child: arbitrarily small spread invalidates unconditional pointwise MomentKV dominance

MomentKV v1 (arXiv 2606.01563), Eq9/11/12 with Algorithm1, Appendix B.2, states correction is always at least as accurate as plain eviction. Construct one retained token R (test score0, value M=tanh(t)) and two evicted tokens with future scores +/-t and values +/-1. The exact evicted conditional output is tanh(t)=M, so full attention output and retained-only output both equal M for every t>0. But the published moment correction predicts (M+2t)/3, with strictly positive absolute error

\[ E(t)=\frac23(t-\tanh t)=\frac{2t^3}{9}+O(t^5)>0. \]

For t=.01, E≈2.22213e-7, and for t=.05, E≈2.77500e-5. This is a stronger arbitrary-small-spread falsifier than the earlier large t=8 example, but does NOT contradict that the first-order approximation can be useful on average.

**Algorithm 1 selection feasibility.** Let the previous query give retained R score L and the two E scores0. Choose L=1+max{log(1/M), log[2/(1-M)]}. In the first eviction, attention-weighted value-residual criterion keeps R because exp(L)M>1. After one E has been evicted, its centered cross-moment is zero (singleton); the remaining E has residual2 and R residual at least1-M, so exp(L)(1-M)>2 keeps R and evicts the remaining E. The CPU probe reproduced this order at t=.01,.05,.1,1. As t->0 the required old L grows; a fixed bounded-logit architecture need not make all arbitrarily small examples reachable. This is a precise equation/algorithm-level claim, not a verified released model/system failure.

**Certification and bytes.** Using R009's conservative bound with extra key/value norm envelopes on 20,000 scalar synthetic caches drawn from t~Uniform(0,2), retained b~N(0,1), the compact CPU probe certified ~18.53% of corrections, while ~86.255% would genuinely help; false certifications observed 0 (as expected from the sufficient theorem). This is not native validation. At dk=dv=128, FP32 dense moment+means+count+two FP32 norm envelopes cost 66,576 bytes per head, equalling 128.03 BF16 full KV entries including int64 positions; with BF16 moments overhead is 33,296 bytes, equalling 64.03 such entries. They are *stipulated storage layouts*, not an authentic MomentKV implementation memory trace. Certificates can be too conservative; exact entries, clipping, full-cache fallback and randomized Xie certificates are stronger controls.

**Closest prior:** Xie, arXiv:2607.21475 already shows post-deterministic-deletion error nonidentifiability and negative gated escalation in real tasks; DefensiveKV (arXiv:2510.13334) handles worst-case eviction fragility. No verified MomentKV author implementation was available in the inspected sources, so no code-benchmark result is claimed. **Next:** separate real Work proof/code review, pin actual released method if available, then task-level query-direction-switch evaluation against byte-matched simple controls, including negative/failure cases, real cache bytes, transfer and recomputation.
