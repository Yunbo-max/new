# R014-C: Value-sensitive planted retrieval and MomentKV Eq(35) audit

**QKV-C exact criterion.** For one target token with score s*, value v*, background partition Z_B=sum exp(si) and weighted background value mu_B, its mass is p*=exp(s*)/(exp(s*)+Z_B). Exact immediate output change upon evicting the target is p*(v*-mu_B); after the fixed output projection its norm is p* D where D=||W_O(v*-mu_B)||. When D>tol>0, projected error at least tol iff s*>=log Z_B+log(tol/(D-tol)); for D<=tol no target score forces error strictly above tol. CPU seeded isotropic synthetic 128D, N65536: logZ_B=11.587297, planted s*=sqrt128=11.3137085, p*=.43202636. With SAME Q/K, D=0 gives 0 loss, D=1 gives .432026 and D=2 gives .864053. At tolerance .2 the score thresholds for D=1 and 2 are 10.2010 and 9.3901. This is a standard exact attention identity (not a new method), with distinct downstream autoregressive effects unmeasured.

Closest controls: exact-key adaptive selection, same-byte plain eviction, MomentKV/ResKV, Certified Sparse Attention arXiv:2610.24991 (which can still scan all original keys). Native query-aligned score and projected V/W_O contrast measurements plus task NLL are required. Falsifier: high-mass target often has no downstream value contrast, or same-resource adaptive exact selection keeps it.

**QKV-C child: independent algebra error in MomentKV v1 Appendix B.2 Eq(35).** In the original HTML primary text https://arxiv.org/html/2606.01563v1, w_R=a/[a+(1+eps)b], hatw_R=a/(a+b), hatw_E=b/(a+b) for a=Z_R>0,b=hatZ_E>0,eps=(Z_E-hatZ_E)/hatZ_E>=0. Direct subtraction yields:
hatw_R - w_R = eps * w_R * hatw_E
 = eps * hatw_R * hatw_E/(1+eps*hatw_E).
But printed Eq35 last RHS has **w_R** in the second formula together with the extra denominator; that is not an identity. Realizable logits: retained logit0, evicted logits -ln2±arcosh2, hence a=1, b=1, Z_E=2, eps=1. True weight gap 1/6=.1666667; printed final RHS 1/9=.1111111. Numerically verified. This is a formula-level likely algebraic typo; it does NOT invalidate MomentKV average benchmark metrics or establish any new architecture. Formal reviewer must independently inspect typeset PDF/equation before publication claims.

**General finite-order moment impossibility, not novel.** For any integer p>=0, evicted scalar keys ki=i, i=0,...,p+1 and values v_i^±=1±A(-1)^i binom(p+1,i) have identical low-order moments sum(v_i ki^r) for all r<=p; all key-only moments agree as keys coincide. Yet the future exponential numerator difference is 2A(1-e^t)^(p+1)!=0 for t!=0. Appropriate A and one common retained token with value0 make true full outputs straddle zero. CPU checked p=1,2,3; opposite signed worlds and equal stored moments. This is a classical finite-difference/truncated moment witness, strictly weaker than the broad deterministic deletion no-identification result already in Xie arXiv:2607.21475v1, and has not been shown reachable under arbitrary p of MomentKV Algorithm1. More moments, clipping, meta-certificates or damping alone are not novel ideas. Reviewer/source-code/byte-parity native tests remain blockers; no official implementation verified.
